# English/Spanish i18n Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make every user-facing UI string translatable with complete English and Spanish translations, add a Settings page to switch language at runtime, and persist the choice — with no hardcoded UI text left in the presentation layer.

**Architecture:** Official Flutter gen-l10n (ARB files + `flutter_localizations`) generates a type-safe `AppLocalizations` accessed via a `context.l10n` extension. A Riverpod `localeProvider` (default Spanish) is the single source of truth for the current locale and persists the choice through the existing `StorageService`. `MaterialApp.router` watches the provider so switching is instant. UI strings are migrated file-group by file-group; product/catalog names remain literal data.

**Tech Stack:** Flutter, Dart, `flutter_localizations`, `intl` (already present), `flutter_riverpod` 2.6.1, Beamer routing, Hive / SharedPreferences storage.

## Global Constraints

- Default language on first run: Spanish (`es`).
- Supported locales: English (`en`) and Spanish (`es`) only.
- Template ARB file: `app_en.arb`; every key added to it MUST also be added to `app_es.arb` in the same task (parity is never broken between tasks).
- Product/catalog names (the Spanish item lists in `lib/core/constants/app_constants.dart` and any Firestore product data) are NOT translated — they stay as literal data.
- App brand name "GreenChain" (`AppConstants.appName`) is NOT translated.
- Access strings via `context.l10n.<key>`; never re-introduce a hardcoded UI string.
- Riverpod providers follow the existing functional style (top-level `final xProvider = ...`) as in `lib/presentation/providers/firebase_providers.dart`.
- No new third-party dependencies beyond `flutter_localizations` (SDK).

### Task 3: Locale provider (default Spanish, persists on change)

**Files:**
- Create: `lib/presentation/providers/locale_provider.dart`

**Interfaces:**
- Consumes: `StorageService` (`getLocale`/`setLocale` from Task 2), `StorageServiceFactory.instance`.
- Produces:
  - `final localeProvider = StateNotifierProvider<LocaleController, Locale>(...)`.
  - `class LocaleController extends StateNotifier<Locale>` with `void setLocale(Locale locale)` (updates state and persists the language code).
  - The provider defaults to `const Locale('es')` and is overridden at startup with the persisted value if present.

- [ ] **Step 1: Create `lib/presentation/providers/locale_provider.dart`**

```dart
import 'package:flutter/widgets.dart';
import 'package:flutter_riverpod/flutter_riverpod.dart';
import '../../core/storage/storage_service.dart';

/// Locales the app supports. Spanish is the default.
const supportedAppLocales = [Locale('es'), Locale('en')];
const defaultAppLocale = Locale('es');

class LocaleController extends StateNotifier<Locale> {
  LocaleController(this._storage, Locale initial) : super(initial);

  final StorageService _storage;

  void setLocale(Locale locale) {
    state = locale;
    _storage.setLocale(locale.languageCode);
  }
}

/// Overridden in main() with the persisted locale (or the Spanish default).
final localeProvider =
    StateNotifierProvider<LocaleController, Locale>((ref) {
  throw UnimplementedError('localeProvider must be overridden in main()');
});
```

- [ ] **Step 2: Load persisted locale and override the provider in `main.dart`**

In `lib/main.dart`, add imports at the top:

```dart
import 'package:flutter/widgets.dart';
import 'presentation/providers/locale_provider.dart';
```

Then, after `await storageService.init();` and before `runApp(...)`, load the saved locale and override the provider:

```dart
  final savedCode = await storageService.getLocale();
  final initialLocale = savedCode == null
      ? defaultAppLocale
      : (savedCode == 'en' ? const Locale('en') : const Locale('es'));

  runApp(
    ProviderScope(
      overrides: [
        localeProvider.overrideWith(
          (ref) => LocaleController(storageService, initialLocale),
        ),
      ],
      child: const VegShopApp(),
    ),
  );
```

Remove the previous plain `runApp(const ProviderScope(child: VegShopApp()));` line (replaced by the block above).

## String migration tasks (6–11)

Tasks 6–11 each migrate one file group. **Every migration task follows the same procedure** (repeated in each task so it can be executed independently):

**Migration procedure for a file:**
1. Open the file and find every user-facing string literal: `Text('...')`, `title:`, `label:`, `labelText:`, `hintText:`, `tooltip:`, `SnackBar(content: Text('...'))`, `AlertDialog` titles/content, button child text, `AppBar` titles, and any string interpolation shown to the user.
2. For each string, choose a descriptive camelCase key namespaced by area (e.g. `loginTitle`, `shopAddButton`, `adminHistoryEmpty`).
3. Add the key with the **English** value to `lib/l10n/app_en.arb` and the **Spanish** value to `lib/l10n/app_es.arb` (parity required).
4. For strings with dynamic values, use ARB placeholders/plurals instead of concatenation. Example ARB (en):
   ```json
   "itemsCount": "{count, plural, =0{No items} =1{1 item} other{{count} items}}",
   "@itemsCount": { "placeholders": { "count": { "type": "int" } } }
   ```
   and call `context.l10n.itemsCount(list.length)`.
5. Replace the literal in the widget with `context.l10n.<key>` (add `import '.../core/l10n/l10n_extension.dart';` — path relative to the file).
6. **Do NOT touch** product/catalog names sourced from `AppConstants.predefinedItems`/`paperOrder`/Firestore, or `AppConstants.appName`.
7. Run `flutter gen-l10n` then `flutter analyze <files>`; expect no errors and no undefined `l10n` getters.
8. Run the app, visit the affected screens, toggle language in Settings, and confirm every migrated string switches and none stays hardcoded.
9. Commit.

**Worked example (applies the procedure to a real snippet):**

Before:
```dart
AppBar(title: const Text('Add Item')),
// ...
ElevatedButton(onPressed: _save, child: const Text('Save')),
```
`app_en.arb`: `"addItemTitle": "Add Item", "save": "Save"`
`app_es.arb`: `"addItemTitle": "Añadir artículo", "save": "Guardar"`
After:
```dart
AppBar(title: Text(context.l10n.addItemTitle)),
// ...
ElevatedButton(onPressed: _save, child: Text(context.l10n.save)),
```
(Note `const` is dropped where the value is now runtime-resolved.)
